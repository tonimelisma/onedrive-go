# onedrive-go: splitting `internal/sync` — end-state design and evidence

Written 2026-11-10 against onedrive-go `70301c0e` (`main`). Nothing in
onedrive-go was changed. This directory holds the design for turning the one
`internal/sync` package into seven packages, and the tooling and ledgers that
show the design is legal Go.

**Read `end-state.md`.** It is the whole design: packages, every dependency
between them and how each is resolved, tests, external consumers, and the
onedrive-go gates the split touches. Everything else here backs it up.

## What the evidence is

A declaration-level simulator (`tools/endstate/endstate.go`, standard library
only) type-checks the production and test files of `internal/sync`, attributes
every reference from the declaration that makes it to the declaration it names,
and checks it against the package each declaration is assigned to in a
configuration file. Verdict for the final configuration, Linux and macOS file
sets:

```
typecheck errors 0, violations 0, cycles 0, interface problems 0,
split const blocks 1, name collisions 2, illegal test references 0
import graph: ACYCLIC
```

The split const block and the two name collisions are explained in
`end-state.md` (sections 8 and 5). It is a model, not a compiled split tree;
`end-state.md` section 14 lists what is estimated and what is not measured.

## Re-running

Run from this directory, with onedrive-go at the pinned commit (`run.sh`
defaults to `~/src/onedrive-go`).

```
tools/run.sh conf/production.txt <out-prod>
tools/mkconf.py conf/production.txt conf/tests.txt <out-prod> conf/final.txt
tools/run.sh conf/final.txt <out>
go -C ~/src/onedrive-go run $PWD/tools/lintmodel/lintmodel.go -repo ~/src/onedrive-go -decls <out>/rawdecls.tsv -out <out>/wrapcheck.tsv
go -C ~/src/onedrive-go run $PWD/tools/shapecheck/shapecheck.go -repo ~/src/onedrive-go -decls <out>/rawdecls.tsv -names <names>
```

- The output directory also receives `rawdecls.tsv`, `rawrefs.tsv`, `refs.tsv`
  and `testdecls.tsv` (about 7 MB). They are regenerated by every run and are
  not saved here; the checkers and query scripts read them from `<out>`.
- `<names>` for the shape check is the list of names the design introduces or
  capitalises for tests (`Type.Method` or `Func`); `linux/shapecheck.txt` says
  which groups were passed.
- macOS file set: `go run` under `GOOS=darwin` would build the simulator for
  macOS. Build it natively first
  (`go -C ~/src/onedrive-go build -o <bin> $PWD/tools/endstate/endstate.go`),
  then run the binary with `GOOS=darwin GOARCH=arm64 CGO_ENABLED=0` and the same
  flags `run.sh` passes.
- Two tied rows in the report's field-reach list may swap order between runs.

Query scripts (usage is in each file's header): `tools/q.py` (why a test
reaches a symbol, who uses a helper), `tools/edgeview.py` (symbols on one edge),
`tools/adhoc.py` and `tools/adhoc2.py` (file, test and export breakdowns).
