# W31 Definition of Ready: a request the transport timed out is retried, not read as shutdown

Worktree `~/src/onedrive-go-wt/transport-timeout-is-not-shutdown`, branch `fix/transport-timeout-is-not-shutdown`, base `3e5c1bd4`.

1. PASS **Task intent**: shutdown is a fact about the run, never about the shape of an error. A sync action, a delta page, a remote or mount-root poll, or a watch observer whose request timed out while its run goes on fails like any other network failure: it is retried, recorded and shown, instead of being dropped as a shutdown (or, for the remote observer, ending the observer silently).

## Cancels narrower than the run (decision 3)

The run is the engine run's context (`beginRun`). The worker's run context is the pool context it is started under.

| File | Function | What it cancels | Cause today | After | Class of an action it reaches |
|---|---|---|---|---|---|
| `internal/sync/worker.go` | `executeAction` | per-action context; canceled by `defer` after the action returned; also stored in `trackedAction.Cancel`, which nothing calls | none | `WithCancelCause`, `errActionReturned`; dead field removed | none: it lands after the action returned |
| `internal/sync/worker.go` | `Start` / `Stop` | the pool context every worker runs under; `Stop` runs when the pass or the watch ends | none | `WithCancelCause`, `errWorkerPoolStopped` | the worker's run ended: shutdown |
| `internal/sync/engine_run_once.go` | `executePreparedPlan` (cancel called in `handleOneShotCompletion`) | the pass context the pool is started under; canceled by a fatal completion (the run then returns that fatal) and at pass end | none | `WithCancelCause`, `errOneShotPassFailed` (fatal) and `errOneShotPassEnded` (pass end) | the worker's run ended: shutdown |
| `internal/sync/engine_timer_panics.go` | `beginRun` (cancel called by `timerPanics.record`) | the run itself, on a timer panic and at run end | none, deliberately (documented in `domain_clock.go`) | unchanged: not narrower than the run | shutdown |

Timeouts narrower than the run (not cancels) that an action can see: the detached store-write bounds (`OutcomeCommitTimeout`, `commitOutcome`, executor records) and every HTTP timeout. With a live run each ends as a request timeout (retry work), not a shutdown.
