## Deviations (behaviour, scope, interface)
- Both `drive add` paths check the account's login first; a configured shared drive without a login now fails instead of "already configured" (completing needs the owner).
- A shared folder's `sync_dir` comes from collision-free `DefaultSyncDir`; equal to the old `BaseSyncDir` unless that path is taken (the old code then wrote two drives into one folder).
- `AddDrive` refuses to write a config strict loading would reject (e.g. nested sync directories) and writes nothing when the enrollment is complete (the analysis said the catalog is always upserted).
- Interface: `AddDrive(*AddDriveRequest, *slog.Logger)`; `Completed` (not `Repaired`); `Login *AccountLogin` field; `drive add --json` always carries `display_name`; `completed` added to `drive add` and `login` JSON and text.
- The catalog is refused whole (every command fails with the file, record, field and repair) when a key or ID reference does not parse; it also requires a record's `canonical_id` to equal its key, beyond the four named fields, so readers need no empty-field fallback. `AccountCanonicalIDByEmail` now returns an error.
- A catalog write that would store a malformed or non-rendered ID fails with the decoder's error and leaves the file as it was.
- `SetDriveKey` writes by the key's kind: a bool key refuses anything but true/false, a string key is always quoted, a list key or a key outside the schema is refused; the file is then unchanged.
