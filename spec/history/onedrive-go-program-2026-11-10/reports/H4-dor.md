# Definition of Ready: enrolling a drive is one transaction owned by `internal/config`

Worktree `~/src/onedrive-go-wt/config-add-drive`, branch `refactor/config-add-drive`, base `27e76cc3`.

1. PASS **Task intent**: `drive add` (own drive and shared drive) and `login` enroll a drive through one `config.AddDrive` transaction: config lock then catalog lock (one lock when both live in one directory), everything read and decided under them, sync directory first, catalog second, the config written once as the commit point, the catalog snapshot written back when that write fails. A failure leaves config and catalog as they were; a kill leaves at most an empty directory and a catalog record without a section; a rerun completes an enrollment an earlier run left incomplete and reports it as completed (text and JSON). `internal/cli` rolls nothing back; login only puts the previous token back.

No new lock, no second wait bound: the `configLocker` from `mutation_lock.go` (bounded poll, `ErrConfigLocked`) is reused. No live runs.
